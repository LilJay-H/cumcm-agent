## 1. 结论

v0 已从题面原文跑通“问题分析—调研—方案选择—独立审核—代码求解—图表—结果解释—中文论文—论文审核—PDF 渲染—机械评测”。最终产出 17 页中文 PDF、完整求解程序、统一结果 JSON 和 3 张 300 dpi 图。机械完整性检查 9/9 通过，原始失败阶段均有显式记录和恢复记录。

这是一份可复现的端到端基线，不是可直接冲击国一的成品。最主要质量缺口是：初次网络调研未取得 BLS/O*NET 数据，模型核心参数仍为情景假设，结论只能解释为条件预测，不能解释为真实就业人数预测。

## 5. 真实失败案例与处理

| 失败 | 原因 | 处理 | 是否形成长期机制 |
|---|---|---|---|
| Windows 无法直接启动 `claude.cmd` | Python 子进程对 `.cmd` shim 兼容问题 | 通过 `cmd.exe /d /s /c` 启动 | 是，运行时适配器 |
| 返回惰性 `<tool_use>` XML | 适配后端会把工具轨迹放进文本结果 | 归一化并剥离工具轨迹 | 是，含回归测试 |
| Claude WebSearch API 400 | 后端不支持该服务端工具 | 新增本地检索/抓取/来源台账模块 | 是，但抓取覆盖仍有限 |
| 求解代码生成超时 | 单次上下文和目标代码过长 | 紧凑提示词、仅传方案与审核、限制 320 行、支持 resume | 是 |
| 整篇论文重写超时 | 长论文输入输出超过适配后端稳定区间 | 改为“论文审核检查点 + 确定性局部整理” | 是 |
| 论文表格与图注排版错误 | LLM 生成多级表头不符合 Pandoc，图片 alt 被识别为自动图注 | 扁平表头、去重图注、渲染后抽页视觉检查 | 部分；通用表格 lint 待补 |

## 6. 尚未解决的质量缺口

1. 核心任务向量、替代/增强弹性和基准增长率没有用职业级观测数据标定，当前模型是情景分析。
2. BLS/O*NET 受 403 和数据格式限制；本地来源工具尚不支持 PDF 解析、结构化 API、附件下载和数据许可证记录。
3. 论文审核能指出公式—代码不一致，但 v0 的确定性整理只修复已配置的问题；尚无通用的“差异补丁—重新求解—回归验证”闭环。
4. 机械 9/9 只证明结构完整、文件存在和若干数值契约，不代表建模正确或具有国一水准。
5. 当前敏感性分析是参数扫描，不等价于统计置信区间；缺少历史回测、外部验证和误差传播。
6. 三个教育机构的课程映射和多目标权重仍需人工查证与专家判断。

## 7. 下一步优先级

### P0：从“情景模型”升级为“证据标定模型”

- 为 O*NET、BLS、国家统计局等建立结构化数据适配器，保留原始响应、版本、许可证和字段映射。
- 将 `观测量 / 文献参数 / 情景假设` 写入机器可读参数注册表，论文中的每个核心数字回链到证据。
- 增加数据缺失时的阻断策略：允许输出探索稿，但禁止标记为“提交候选”。

### P1：可靠性闭环

- 把求解器拆成模型规格、实现、测试和执行四个可重试节点；加入公式—代码符号对照检查。
- 论文审核改为结构化 issue 列表，逐条生成最小补丁，并在补丁后重新运行数值和渲染回归。
- 增加 Markdown 表格 lint、全部 PDF 页渲染和图表清晰度检查。

### P2：ICML 叙事与消融

- 固化 episode schema：题目、工件 DAG、模型/工具调用、人工介入、费用、耗时、失败与恢复。
- 建立多题 benchmark，并对 `web_research`、`independent_review`、`paper_audit` 做正交消融。
- 将竞赛质量指标与研究指标分开：前者关注论文与模型质量，后者关注自治率、证据可追溯性、恢复率和成本。
