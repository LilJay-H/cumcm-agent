## CUMCM 可执行约束

1. 官方评奖主要标准为假设合理性、建模创造性、结果正确性和文字表述清晰度。因此机械评测不能只检查“文件是否存在”，还应检查假设、数字结果、验证与表达是否闭合。
2. 电子论文第一面为中文摘要，不需要英文摘要，不要目录；正文不超过 30 页，附录需包含完整可运行程序和支撑材料清单。
3. 摘要应在一页内覆盖问题、模型、关键数值、稳健性和主要贡献。只有方法名而没有数字的摘要信息量不足。
4. 程序、运行结果和论文结论必须一致；可复现性是硬门槛。
5. AI 可以辅助，但需要正文标注、参考文献记录工具，并提交“AI 工具使用详情”。因此 v0 默认保存完整调用台账、模型名、提示词、回复、耗时和费用。

## 题型与流程认识

- 国赛本科组近年 A/B 题偏机理、几何、物理与连续优化，C 题常见“真实数据分析 + 决策/优化”。
- 通用链路是：读题与拆解 → 数据审计 → 候选方案竞争 → 形式化模型 → 代码求解 → 验证/敏感性 → 决策建议 → 论文成文 → 数字与引用复核。
- 集训专家材料反复强调：明确数学表达、算法步骤、结果完整准确、可靠性证据；“结果一致”不自动等于“结果正确”，应尽可能加入不同方法、边界条件或反事实验证。

## 从 modeling-harness 吸收的设计原则

参考文件：`modeling-harness/docs/DESIGN.md`、`ARCHITECTURE_V4.md`、配置和评测代码。

采用：

- 把题面、数据、假设、模型、代码、结果、决策和论文视为有依赖关系的异构工件。
- 生成和审核分离；论文不能创造计算阶段不存在的确定性。
- 执行状态与结论是否通过分开记录；失败不可伪装成未运行。
- 工件带哈希、生产阶段和父依赖，便于复跑、比较和消融。
- 评测、阶段耗时、模型用量和完整调用记录作为一等产物。

v0 暂不采用：

- SQLite 租约调度、完整 Problem Graph/Evidence Graph、级联撤销和多代理并发。这些对今晚单机端到端证明过重。
- v0 使用线性阶段编排和工件清单；接口保留后可升级为 DAG 调度。

## 关键设计决策

1. **Claude Code 仅作模型运行时**：本地 Python 编排器掌握路径、工件与执行边界，LLM 不直接写工作区。
2. **文本生成与代码执行分离**：LLM 生成单一求解脚本，受控执行器运行并验证 `results.json` 与图表。
3. **双审核点**：建模方案有独立反方审核；论文有数值与引用审核。
4. **长上下文策略**：长题面按重叠块摘要并保留原文；阶段上下文有总预算和单工件预算。
5. **人机检查点**：分析与方案选择后暂停；测试配置可自动批准但写入决策记录。
6. **消融接口**：网络调研、独立方案审核、论文审核均可单独关闭，并产生显式占位工件。
7. **两类目标分离**：竞赛质量由 CUMCM 完整性指标评估；研究叙事使用阶段、成本、消融和失败轨迹，不用一个总分混淆两者。
